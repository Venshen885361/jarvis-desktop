# 個別科學研究計畫：以蛻變測試與突變分析檢驗語音助理的自然語言意圖路由

> 受測對象：`jarvis/router.py`（J.A.R.V.I.S. 的本機意圖路由，約 60 條 regex / 關鍵字規則）
> 工具：`research/mt/`（全部自己寫、可重跑）；資料：`research/mt/out/`（不進 git）

## 0. 一句話

輸入是自然語言、沒有標準答案的路由元件，要怎麼**自動產生測試、知道哪些測試有用、留多少、先跑哪些**——用 J.A.R.V.I.S. 當真實案例，做完整一輪並回饋到產品。

## 1. 研究問題

| RQ | 問題 | 怎麼答 | 狀態 |
|---|---|---|---|
| RQ1 | 蛻變關係自動生成的測試，能否找到手寫測試沒抓到的路由錯誤？LLM 生成與規則式生成誰找得多、找得不一樣？ | 兩種生成器 × 5 條關係，數違反、去重後的錯、獨有的錯 | **已有數據**：第一次 928 句 → 433 違反；LLM 找到的去重錯是規則式 2 倍，且互補（rules-only 剩 1–2 個） |
| RQ2 | 生成參數（溫度）與 LLM 非確定性對測試品質的影響 | 4 個溫度 + 同溫度重跑，量句子重疊（Jaccard）、錯集合重疊、有效率、多樣性 | **已有底線**（E2，六批都是 41 條種子）：T=0 跑三次兩兩句子 J=0.22–0.24、錯 J=0.43–0.59；溫度兩兩 J=0.23–0.26、錯 J=0.51–0.59 → 溫度差異 ≈ 重跑雜訊；殺傷力也是（溫度 327–345 vs T=0 重跑 331–341；原本的 T0 329 > T1 243 是去重順序的假象）。**n=20 放大四倍後結論不變**（錯集合 J 溫度 0.56–0.59 vs 重跑 0.56–0.58），但批次大小本身有影響：去重錯 110 → 273，多撈到的是填充詞 / 禮貌語 / R5 整句包含的真錯 |
| RQ3 | 這些測試裡多少是多餘的？哪種縮減策略保留最多找錯能力？ | 自寫的 regex 導向突變器 → 測試 × 突變體矩陣 → greedy / HGS / irreplaceable / 隨機 | **有數據**（全批次 3 164 條）：→ 194 條保留 100%，隨機同大小 54%；便宜準則 ≈ 隨機；存活突變體抽樣：等價約 18%；killer 補種子 0.448 → 0.518 |
| RQ4 | 只能跑前 k% 時，哪種排序最早找到錯？ | 同一矩陣：total / additional / relation-first / 隨機，APFD | **有數據**：additional 0.983、隨機 0.81、relation-first 0.70；前 10% 找到 100% |
| RQ6 | 在舊版縮減 / 排序的測試集，程式改版後還有用嗎？ | E7：v4 決定 → v5 評估，反向也算 | **有數據**：v4 → v5 縮減子集保留 84–85%（隨機 50%）、additional 0.901；隔四輪（v0 → v5）只剩 41–43%、additional 0.716 比隨機 0.82 差 |
| RQ7 | 927 個突變體裡多少是獨立的錯？哪些運算子多餘？ | E8：kill vector 包含關係、dominator、最小突變分數 | **有數據**：485 可殺裡 238（49%）是 dominator；只用 ALT_DEL + KW_DEL + CMP 找回 95% dominator、縮減結論不變；隨機子集最小分數 27%（一般 52%）；dominator-APFD 排名不變差距拉大 |
| RQ8 | 自己寫的種子跟真實使用差多少？ | E9：history 的 41 條真實指令當種子，比違反、比殺傷 | **有數據**：真實指令 27% 英文；4 條現行路由就錯（3 條是缺規則，突變測試量不到）；真實批次只多殺 3 個突變體（有哪些裝置 / 框選 / 天氣） |
| RQ9 | 結論是不是只對我的 router 成立？ | E10：同一套跑在 Home Assistant zh-TW 意圖模板（別人寫的、整句匹配、520 條模板） | **有數據**：規則式 985 句 → 596 違反（R4 100%、R2 81%、R5 0%——錯的方向跟 router 相反）、找到「客廳燈幫我打開 → 問狀態」真錯；2 748 個模板突變體，縮減 1 454 → 187（12.9%）保留 100%、隨機 43%，APFD additional 0.956、total 0.790、隨機 0.746、relation-first 0.634（排名跟 router 一樣）；dominator 65%（router 49%），OPT_DEL 多餘比例 51%（router 94%） |
| RQ5 | 找到的錯修回去，路由變好多少？會不會修出新的錯？ | 修正前後各版本重跑全部批次（已做四輪） | **有完整表**（E6，5 版 + 第四輪）：規則式 706 → 7、LLM ~385 → ~90 違反；第二輪修時間規則太嚴、第四輪第一版新壞 3 句，都被蛻變測試批次當回歸集抓回來 |

RQ1、RQ2、RQ5 是「測試生成」；RQ3、RQ4 是「測試集縮減與排序」——後者是指導教授的本行，也是報告的主體。

## 3. 待做實驗（依序）

### E1 有效性人工抽樣（RQ1 的信度，1 週）— 工具已完成：`sample.py`（抽樣 + κ + precision），剩人工標記
`valid%` 現在幾乎 100% 是因為過濾器只檢查「目標詞還在不在」。從每個生成器 × 關係各抽 40 句（共 400），兩個人獨立標「這句是否真的保留原意圖」，算一致度（Cohen's κ）與各生成器的 precision。LLM 語意漂移率（「搜尋晴天」這種）就是這裡量出來的。

### E2 非確定性底線（RQ2）— 已做：`run.py --rep 1 / 2`
T=0 跑三次：句子 J=0.22–0.24、錯集合 J=0.43–0.59，跟溫度之間（0.23–0.26 / 0.51–0.59）分不開；四個溫度共同的錯 38/116 vs T=0 三次共同 39/115。表在 README。四個溫度已用 41 條種子重生（964 句一批）。

### E3 突變測試（RQ3 的 ground truth）— 工具已完成：`research/mt/mutation.py`
不用 mutmut：它改運算子和常數，碰不到 regex 裡的一個分支。自寫 7 種針對意圖路由的運算子（見檔頭表），
`python -m research.mt.mutation` 就產矩陣 `out/matrix_<tags>.csv`。剩下要做的：
1. ~~用全部批次跑~~ 已做：最新 3 355 條 × 927，分數 0.520；每批殺傷用 `--by-batch` 算（去重順序曾造成 T0 > T1 的假象）。
2. ~~存活的突變體人工分類~~ 已做（`survivors.py`）：抽 60，沒覆蓋 77% / 等價 18% / harness 看不到 5%；扣等價後分數約 0.51。每個判斷附可執行的 killer，第一輪人工判斷錯 33%。
3. ~~從存活突變體反推缺的種子~~ 已做：46 句 killer 補進 seeds.json → 分數 0.448 → 0.516；規則式再對它們生 718 句只再 +0.002（詞覆蓋與句型覆蓋正交）。

### E4 縮減（RQ3）— 工具已完成：`research/mt/reduce.py`
在 M 上實作四種策略，各算「縮減後的殺傷率 / 原殺傷率」與「縮減後大小 / 原大小」：

| 策略 | 做法 |
|---|---|
| Greedy（set cover） | 每次挑殺最多「尚未被殺」突變體的測試 |
| HGS（Harrold-Gupta-Soffa） | 先選只被單一測試殺的突變體對應的測試，再擴展 |
| Irreplaceable-first | 指導教授論文的作法：先保留不可取代的測試（唯一能殺某突變體的），再貪婪補 |
| 隨機 | 對照 |

每種跑 30 次（有隨機性的），畫盒鬚圖。**再多做一件**：用「關係 + 種子」當覆蓋單位（而不是突變體）做同樣的縮減，看跟突變體為基準差多少——這是「沒有突變測試時能不能用便宜的替代品」的問題。

### E5 排序（RQ4）— 工具已完成：`research/mt/reduce.py`（同一支）
| 策略 | 做法 |
|---|---|
| Total | 依殺傷數排序 |
| Additional | 每次挑殺最多「尚未被殺」的（跟 greedy 同，但排完整） |
| 關係優先 | R5 近似句先（找到的錯最危險） |
| 隨機 | 對照 |

指標 APFD；畫「跑了前 k% 測試 → 找到幾 % 的錯」曲線。

### E8 突變體包含關係（RQ7）— 已做：`subsume.py`
### E6 回歸重跑（RQ5）— 已做：`versions.py`（sha 已換成 GitHub main 的，v5 補上）

## 4. 效度威脅（報告要自己先講）

- **種子選擇**：41 條原始種子是我挑的，偏向我知道 router 會做的事；46 條 `sv_*` 是對著存活突變體寫的，偏向 regex 的詞表。已做：第三批從實際使用紀錄來（E9），找到 4 個缺規則的錯，殺傷只多 3 個。
- **單一受測對象**：原本只有一個 router。已做：E10 把同一套跑在 Home Assistant zh-TW 意圖模板（41 意圖 / 520 模板、hassil 整句匹配）上——縮減 / 排序的四個結論全部重現，但「哪種突變體多餘」跟 SUT 寫法有關（router 的 OPT_DEL 94% 多餘，HA 只有 51%），E8 的省運算子建議不能照搬。剩下的缺口：HA 沒跑 LLM 生成器、種子是模板展開的不是真實使用。
- **LLM 漂移**：生成的測試本身可能錯，E1 量化。
- **等價突變體**：E3 抽 60 個人工估，約 18%（每個判斷附 killer 驗證；`survivors_manual.json`）。
- **我既是開發者也是實驗者**：修 router 時知道測試長什麼樣。緩解：修正只針對分類後的「原因」，不針對個別句子；golden tests 與生成測試分開。
