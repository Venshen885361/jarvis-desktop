# 蛻變測試 × 自然語言意圖路由（個別科學研究用）

受測對象：`jarvis/router.py` —— 用正規表達式把一句話送到「開程式 / 播音樂 / 家電 / 純問答 / 交給模型」。
輸入是自然語言，沒有 oracle（沒人能列出所有句子的正確答案），所以用**蛻變關係**當判準：

| 關係 | 改寫方式 | 路由應該 |
|---|---|---|
| R1 同義改寫 | 打開 → 開啟 / 啟動 / 幫我開 | 相同 |
| R2 語助詞 | 幫我…一下 / …好嗎 | 相同 |
| R3 換語序 | 記事本幫我開一下 | 相同 |
| R4 無關前綴 | 欸、那個、JARVIS | 相同 |
| R5 近似句 | 不要打開記事本 / 記事本打不開怎麼辦 | **不同**（不該觸發） |

兩個生成器照同一份關係生：`rules.py`（模板，對照組）與 `llm.py`（Gemini，溫度是實驗變因）。

## 跑

```bash
pip install -e ".[gemini]"                       # 只要 google-genai
python -m research.mt.run --gen rules --show-violations
python -m research.mt.run --gen llm --model gemini-3.5-flash-lite --temperature 0 0.3 0.7 1.0 --n 5
```

輸出在 `research/mt/out/`（不進 git）：`tests_<tag>.jsonl` 每條測試一行、`summary_<tag>.json` 各關係統計、`cache/` API 快取。

指標：`valid%`（過濾後留下的比例 = 語意沒漂移）、`viol%`（違反關係 = 路由的錯）、`dist2`（字元 bigram 多樣性）。

## 第一次規則式結果（2026-09-14，router @ 5065037）

| 關係 | 生成 | 違反率 | 代表案例 |
|---|---|---|---|
| R1 同義 | 48 | 14.6% | 「開github.com」走 open_application 而不是 open_url |
| R2 語助詞 | 288 | 48.6% | 「打開記事本好嗎」→ 目標變成「記事本好嗎」 |
| R3 換語序 | 52 | 96.2% | 「記事本幫我打開」→ 交給模型；「下載資料夾幫我打開」→ 變成安裝程式 |
| R4 前綴 | 288 | 41.0% | 「欸 開 YouTube」→ 交給模型（`_BARE_OPEN` 只認句首） |
| R5 近似句 | 252 | 46.8% | 「不要打開記事本」**真的會打開記事本** |

一次跑一秒，928 句，找到 433 個違反——全部是手寫測試沒抓到的。

## 第一輪回饋（2026-09-14，router @ 61b59d0 → 本 commit）

蛻變測試找到的錯，歸納成 5 個原因、改 router 6 處：

| 原因 | 修法 | 影響的關係 |
|---|---|---|
| `startswith` 型規則對任何前綴零容忍 | `_normalize()` 剝句首填充（欸 / 那個 / JARVIS）與外層客氣話（麻煩 / 可以）；搜尋 / 切換 / 複製規則比對前再剝「幫我 / 請」 | R4 41% → 0% |
| 句尾語助詞黏進目標（`open_application("記事本好嗎")`） | `_TAIL_RE` 剝「一下 / 好嗎 / 謝謝 / 喔 / 啦…」 | R2 53% → 2% |
| 否定句、問句照做（「不要打開記事本」真的打開） | `_NEGATION_RE`、`_QUESTION_RE` 守門 → 交給模型 | R5 40% → 0% |
| `_URL_RE` 的 `\w` 吃中文（「開啟github.com」整段變網址） | 網域只認 ASCII | R1 15% → 4% |
| 家電規則不接受「冷氣**溫度**調到」與「請幫我把」 | `_HOME_RE` 放寬 | home_set 70% → 0% |

規則式批次：違反 283 → **52**，去重後的錯 71 → **16**。剩下的 R3（換語序）88% 是已知限制：
「記事本幫我打開」這種目標在前的句型，regex 路由本來就不處理，留給模型。

順帶修了 harness 一個 bug：`computer:key:nexttrack` 解析成 `(computer, key:nexttrack)` 跟路由回的 `(computer:key, nexttrack)` 比對永遠不等，`next_track` 的 77% 脆弱度有一半是這個假象。**測試工具自己也要測**。

## 第二輪回饋（LLM 批次剩下的錯）

LLM 改寫剩下的違反幾乎全是 `X→model`：句型我 regex 沒收。看過 60 句後分成三類：

| 類別 | 例子 | 處理 |
|---|---|---|
| **該收的句型**（真人會這樣講） | 「我要看 YouTube」「把記事本打開」「請幫我播晴天喔」「透過 Steam 來安裝」「幫我載 VLC」「進入 github.com」 | 加：意願句（我要 / 我想 + 看 / 用 / 聽 → 開 / 播）、受詞在前（把 X 打開 / 裝起來）、平台片語（透過 / 藉由 / 裡面 / 上面）、「請幫我」雙前綴、動詞後的「一下」、全形「？」 |
| **關鍵字規則太貪** | 「請幫我播放一下周杰倫」→ 媒體鍵 playpause；「現在幾點才能進去考場」→ 報時 | 媒體鍵只在整句就是那個詞時按；時間 / 日期改成整句比對 |
| **LLM 語意漂移**（測試本身錯） | 「搜尋晴天」（種子是播晴天）、「取得 Discord」 | 不改 router；記成過濾器該抓的案例 |

規則式批次：違反 52 → **50**（剩的是 R3 語序，模板句型本來就不自然）。
`tests/test_router_golden.py` 把每一類留一句進 CI。

## 檔案

| 檔案 | 作用 |
|---|---|
| `harness.py` | 把 router 變純函式：`route_label("幫我開一下記事本") → Label('open_application','記事本')`；所有出口換成記錄器 |
| `relations.py` | 五條蛻變關係的定義（兩個生成器共用） |
| `rules.py` | 模板生成器（對照組） |
| `llm.py` | Gemini 生成器：溫度可調、JSON 輸出、磁碟快取、失敗如實記錄 |
| `run.py` | 生成 → 過濾 → 路由 → 判定 → 報表 |
| `seeds.json` | 36 條種子句與期望路由 |
| `../../tests/test_mt_harness.py` | 煙霧測試（CI 跑） |
